Q/01 Before we start

Questions from L04?

Anything from last lecture still unclear. If quiet, we answer these three.

01

What is the difference between <strong> and bold text in CSS?

<strong> marks content as important — it has semantic meaning. CSS font-weight: bold only makes text look bold, with no semantic weight. Screen readers may announce strong content with extra emphasis.

02

Can a <button> contain an image?

Yes. A button can contain most phrasing content — including an <img>. The image still needs meaningful alt text so screen readers know what the button does.

03

Can you nest a <ul> inside a <li>?

Yes — that is exactly how nested menus work. A <li> can contain another <ul> or <ol>, creating a sub-list. Used for multi-level navigation and outlines.

5 minutes. Let students ask first. Show backup questions one by one.

Without semantics — div soup
With semantic elements

Ask: "which one can a screen reader user navigate with a single keystroke? Which one can Google understand? Which one can a new developer read and immediately know the page structure?" The visual output is identical. The meaning is completely different.

Sem/01 First look

Seven elements that name the page's regions

These landmarks tell browsers, search engines, and assistive technology exactly what each region of the page is for.

landmark <header>

Introductory content for the page or a section — logo, site name, navigation, search. Can appear once per page or once per section.

landmark <nav>

A set of navigation links — main menu, breadcrumbs, pagination. Only for major navigation blocks, not every link group.

landmark <main>

The primary, unique content of the page. Only one per page. Skip-navigation links jump to this. Excludes header, footer, sidebar.

landmark <article>

A self-contained piece of content that makes sense on its own — a blog post, a menu item, a news story, a product card.

grouping <section>

A thematically grouped section of content that would appear in a table of contents. Always needs a heading. Not just a styling wrapper.

landmark <aside>

Content tangentially related to the main content — sidebars, pull quotes, related links, supplementary information.

landmark <footer>

Closing content for the page or a section — copyright, links to privacy policy, secondary navigation, author info.

generic fallback <div>

No semantic meaning. Use only when no semantic element fits — typically for layout containers that group elements for CSS.

Reveal each card. For each one, point to the restaurant page and ask "where would this element go on our page?" The point is that every major region of a well-structured page has a name — and it is not div.

Sem/02 The full picture

Every region has a name

<header> Logo, site name, main nav
<main>
<article> Today's specials
<section> Drinks menu
<aside> Opening hours, special offers
<footer> Copyright, secondary nav
  • <header> — site or section header
  • <nav> — navigation block
  • <main> — unique page content (one per page)
  • <article> — self-contained content unit
  • <section> — thematic grouping with heading
  • <aside> — supplementary content
  • <footer> — closing content

Screen reader users can jump directly to <main>, <nav>, or <header> with a single keystroke. Without these landmarks, they must Tab through every link to find the content they want.

Point at the diagram. Ask: "what is the one element you can only use once per page?" (main). "What does aside mean — is it always a sidebar?" (No — it means tangentially related, not physically on the side.)

Sem/03 The top of the page

<header> and <nav>

<header>

Not just the site header

A <header> can appear inside <article> and <section> too — it introduces that element. Only the top-level header is a ARIA landmark.

<nav>

Only for major navigation

Use <nav> for primary and secondary site navigation, not for every group of links. A list of social icons in the footer is not a nav. Add aria-label if you have more than one nav per page.

Put your navigation links in a <ul> inside <nav>. Screen readers announce the number of items in a list, so users know how long the menu is before reading it.

Show the code. Ask: "why is the nav inside the header — isn't it already a navigation landmark?" Yes, but header and nav are separate concepts. Many designs put nav inside the header, but nav can also live outside it (e.g., a sidebar nav).

Sem/04 The content area

<main>, <article>, and <section>

<main>

One per page — no exceptions

The dominant content of the page. Don't put the header or footer inside it. Screen readers let users skip directly to <main>.

<article>

Self-contained and syndicatable

Would this content make sense if extracted and published separately (an RSS feed, a social share)? If yes, use <article>. A menu, a recipe, a news story, a product are all articles.

<section>

A chunk with a heading

Groups related content under a heading. If you cannot give it a heading, it probably needs to be a <div>. Use sections to create the page's outline.

The article vs section confusion is very common. Test: "if I ripped this out and put it on another page, would it still make sense?" Article = yes. Section = no, it needs context from the surrounding page.

Sem/05 The supporting cast

<aside> and <footer>

<aside>

Tangentially related — not just a sidebar

Content that adds to but is not essential to the main content: opening hours, a related recipe, a glossary term, an advertisement. The name "aside" is about the relationship — not physical position.

<footer>

Can appear more than once

Like <header>, a footer can appear inside an <article> to hold publication dates, author info, or tags. The page-level footer is a landmark — the article footer is not.

Common mistake: using aside just to style something on the side. Aside is about the relationship with the main content — if you removed the main content, would the aside still be useful? If yes, it should not be an aside. Use a div or section instead.

Sem/06 Why it matters

Three reasons — and only one is optional

Accessibility

Screen reader users navigate pages by landmarks: jump to nav, jump to main, skip to footer. Search-and-jump is only possible with semantic landmarks. ~15% of the world has a disability that benefits from this. Not optional.

SEO

Search engines use semantic elements to understand page structure. An <h1> inside <main> inside <article> ranks higher than the same text inside three divs. Google has published guidance on this directly. Not optional.

Maintainability

A developer who reads <header>, <main>, <aside> immediately understands the page layout. A developer who reads <div class="wrapper1"> has to guess. Code you write today will be maintained by someone else next year. Optional — but kind.

Semantic HTML is free. It costs no performance, no bundle size, no extra code. It is the same number of tags. The only cost is learning which element to use. You are learning it now.

The accessibility argument is the strongest. Ask: "how many of you have ever used a keyboard only (no mouse) to navigate a website?" Try it now. Tab through the current page. Can you reach every link and button? That is what screen reader users experience, magnified.

CSS/01 The second language

CSS is the styling language of the web

HTML

Structure and meaning

What is on the page and what it means. Content, hierarchy, relationships.

CSS

Presentation

How everything looks. Color, typography, layout, spacing, animation. CSS never changes the HTML's meaning — only its appearance.

JavaScript

Behaviour

What happens when the user interacts. Click handlers, API calls, DOM updates.

One CSS file can style an entire website. Change one rule — every page updates.

Connect CSS to HTML with <link rel="stylesheet" href="style.css"> in the <head>. One link can apply styles to every page that includes it.

Make the analogy concrete: HTML is the building (walls, floors, rooms). CSS is the interior design (paint, furniture, lighting). JavaScript is the electrical system (what happens when you flip a switch). Changing the paint does not move the walls.

CSS/02 Anatomy of a rule

Every CSS rule has this shape

Selector, property, value. That is the entire language — the rest is vocabulary.

h1
selector
{
    
color
property
:
#2456c5
value
;
}

Selector

Which elements?

Points at the HTML elements this rule applies to. Could be a tag name, a class, an id, or a combination. We cover these in detail next.

Property

What to change?

The specific aspect to style: color, font-size, background, margin, padding, display, and hundreds more.

Value

How to change it?

Specific to the property: colors take hex/rgb/names, sizes take px/rem/%, keywords like bold or center, and so on.

Type this live. Point at each part. "The semicolon at the end of each declaration is required. Forgetting it is a common bug — the next property stops working." Show: write two properties, remove the semicolon from the first, see the second break.

CSS/03 Three locations

Three places to write CSS — only one is right

Option 1

Inline

Directly on the element with the style attribute.

Avoid in production

Hard to maintain, difficult to override. Fine for quick tests and JavaScript-driven dynamic styles. Not for general styling.

Option 2

Internal

A <style> block inside <head>.

For single pages only

Fine for a single-page prototype. Doesn't share styles across multiple pages. Forces you to copy styles if you add a second page.

Option 3

External file

A separate .css file linked from <head>.

Always use this

One file styles all pages. Browser caches it — pages load faster on second visit. Easy to maintain, easy to share. This is what we use from here on.

Type all three options. For each: "what breaks when you add a second page?" Inline: have to repeat the style on every element. Internal: have to copy the block to every HTML file. External: change one file, all pages update. The cascade comes from here.

Click a rule to see which elements it targets.

Type selectors are powerful but broad. Styling all p elements means every paragraph on every page gets the same style. Use with care on large sites.

Show the demo live. "When I write p { color: navy; } — which elements light up?" Ask before clicking. Then discuss: "what if I want only SOME paragraphs to be navy? I need a more specific selector — a class."

Sel/02 The most used selector

Class selectors target specific elements

Syntax

Dot + class name

In HTML: class="special". In CSS: .special. The dot is the class selector prefix — it only appears in CSS, never in the HTML attribute.

Reusability

One class, many elements

The same class can go on any element — <p>, <li>, <div>. One CSS rule targets all of them. This is why classes are the default tool for styling.

Multiple classes

Space-separated in HTML

class="special featured" applies both rules. The element gets all the styles from both classes — they stack.

Type live. Show that adding class="special" to an h2 also gets the color rule — the class works on any element, not just p. Then show stacking two classes. "This is how CSS frameworks like Tailwind work — every utility is a class."

Sel/03 The unique selector

ID selectors: powerful, but limited

Syntax

Hash + id name

In HTML: id="reserve". In CSS: #reserve. The hash is the id selector prefix. The id must be unique — only one element per page can have a given id.

Why we prefer classes

IDs are hard to reuse and override

An id has higher specificity than a class — it is harder to override later. And because ids must be unique, you cannot reuse the style on a second element. Use id for JavaScript hooks and anchor links. Use classes for styling.

The specificity point will come in the next lecture. For now: "think of ID selectors as a VIP pass — very powerful, but you only get one, and it is hard to take back. Classes are regular tickets — unlimited, easy to reuse." In practice, most CSS frameworks use no ID selectors at all.

Sel/04 Selector patterns

Four ways to combine selectors

Grouping (comma)

Same rule for multiple selectors

Descendant (space)

Element inside another element

Element + class (no space)

Only this element with this class

Pseudo-class (:)

Based on state

Cascade and specificity — what happens when two rules target the same element — is covered in the next lecture. For now: the rule written later in the file wins when selectors have the same weight.

Type each pattern live and watch the element change in the browser. The descendant selector surprises students: "nav a means 'any a that is inside a nav, at any depth.'" Show that nav a does NOT affect links outside the nav. The pseudo-class :hover is usually the moment students first feel CSS is alive.

Sum/01 You explain it

Cover the card. What's on the other side?

01

Name four semantic landmark elements.

Reveal

<header>, <nav>, <main>, <article>, <section>, <aside>, <footer>. Any four counts.

02

Why not just use <div> for everything?

Reveal

A div conveys no meaning. Semantic elements tell browsers, screen readers, and search engines what each region is for — enabling navigation, indexing, and accessibility.

03

What are the three parts of a CSS rule?

Reveal

Selector — which elements. Property — what to change. Value — how to change it. Written as: selector { property: value; }

04

How is a class selector written differently in HTML and in CSS?

Reveal

In HTML: class="special" — no dot. In CSS: .special — dot prefix. The dot is only in the CSS selector, never in the HTML attribute.

05

When should you use an ID selector vs. a class selector for styling?

Reveal

Prefer class selectors for styling — they are reusable and easier to override. Use IDs for JavaScript hooks and anchor links. IDs have higher specificity and are harder to override.

06

What does article mean — when do you use it?

Reveal

A self-contained piece of content that makes sense on its own if removed from context — a blog post, a menu item, a product card, a news story. It does not mean "the main content area."

6 minutes. Students explain each card to a neighbour first, then you reveal. Pay attention to who hesitates on the article vs section question — that distinction trips people up even after years of web development.
